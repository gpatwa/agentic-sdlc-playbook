How it works · one real run

Every change takes the same six steps.

Our public ask-the-docs service counted its model spend wrongly in three small ways: a retry could take it past its daily cap. This is how Aveto fixed it, step by step, quoting the run’s own records.

  1. 1 · You approve

    One Charter, approved by its hash.

    Scope, models, spend and stops in one file. Nothing outside it happens without asking.

    APPROVAL_RECORD-1.md“I approve runs/fix-service-accounting/CHARTER.md, sha256 afc984d1…aefe4, with plan 730k, ceiling 950k, hard cap 1,200k.”

  2. 2 · Spec

    How it will be checked, before the build.

    The architect maps every “done means” line in your intent to a test that must fail on today’s code.

    05-tech-spec.md#6 fixed, test fails first | §1 (option A), §5 tests T6.1 (fail-first), T6.2

  3. 3 · Build

    Tests fail first, then pass.

    New tests are run on the old code and must fail with the figures the spec named.

    END_REVIEW.md30 tests fail on 87178bd with the figures the spec named (…), and pass on the branch.

  4. 4 · Evidence

    QA and security, by roles that did not write it.

    QA reproduced the failing list on its own. Security tried every two-attempt outcome through the real adapter: 144 sequences.

    14-security-review.mdVerdict: PASS … No blocker, no required fix.

  5. 5 · Independent review

    Every finding recorded.

    A reviewer that did not write the code sets a risk tier and records each finding as fixed, rejected or intentional.

    code-review.md5 findings (0 Important, 3 Nit, 1 Pre-existing, 1 behaviour note routed to Docs). Tier: High.

  6. 6 · You decide

    A pull request, and the choices that are yours.

    The run ends with what changed, what it cost, and what it could not decide for you. You merge.

    END_REVIEW.mdThe daily pause comes at about 33 questions, not the intent’s 41.

Spent 919k tokens of a 1,200k hard cap (subagent stages only). The record also lists the run’s misses and open risks, such as a rollback not rehearsed. Read the whole run →

What holds on every run

Rules the agents cannot talk their way past.

It refuses work it shouldn’t build.

Intake checks a request against your recorded safety invariants. Given a request to auto-purge user data with no confirmation, a run stopped before any code was written.

The verifier never wrote it.

QA, security and the release gate are separate roles from the one that wrote the code. A failed gate sends the work back, never forward.

Only a person approves.

Aveto’s approval binds a hashed Charter: scope, models, spend and data processors. Other tools approve a plan or a task; some record the approval by agent. An approval typed in another session does not count.

What it runs on

The Claude Code plan you already pay for.

Aveto never resells inference and adds no API bill for the build. Usage still counts against your plan’s limits, so a long run can pause.

What it is not

Where it costs you, and where it isn’t proven.

  • Not free to run. Each stage forms its own judgement, so a run spends real tokens from your plan.
  • Not for a one-line fix. Small changes take a shorter path, and the reason is recorded.
  • Not a team product yet. Built and proven by one person on one subscription. Shared team gates are on the roadmap.
  • Not a certification. It keeps a record of who approved what; no auditor has used it.
  • Not a hosted service. It runs in your Claude Code session, and only Claude Code.

Common questions

Straight answers.

Is this a coding agent?

No. Aveto directs the agents you already use rather than replacing them. It sits a layer above the worker; today that worker is Claude Code.

Do I have to approve every step?

No. You approve one Charter at the start, by its hash. The run stops only for an action the Charter does not name, for spend past its hard cap, or for a credential. The default Charter allows no merge, no deploy and no send: a run ends with a pull request for you.

Why a subscription instead of an API key?

Because it changes who carries the cost. Aveto runs on the Claude Code plan you already pay for, so it adds no separate API bill. The scarce resource is that plan’s usage window, which is why every stage is costed before it spends.

How is this different from other tools?

Many tools have a plan step and an audit log. Aveto’s difference is what is approved and by whom: one hashed Charter that fixes scope, models, spend and processors, approved by a person. The trade is breadth: Aveto is narrower and Claude Code only.

Does it work for a team?

Each developer running their own slices on their own subscription works now. Shared gates across a team and a run inventory across developers are on the roadmap, not shipped.

Let the agents do more.

Aveto is open. Point the installer at a repo and it writes one least-privilege agent per role, the gates, and the commands to run a slice.
