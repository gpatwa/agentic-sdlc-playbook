| F-01-1 | P0 | app/api/users.py:64-79 | `PUT /api/users/<id>` has no ownership check. Any holder of a valid API token can edit any other user's `username`, `email` and `about_me`. Registration is open (`POST /api/users` has no auth), so anyone can get a token. An attacker changes the victim's email to their own, then uses the password-reset flow to take over the account. `abort` is imported but never used, so the 403 guard looks to have been removed. | `@bp.route('/users/<int:id>', methods=['PUT'])` / `@token_auth.login_required` / `def update_user(id):` / `user = db.get_or_404(User, id)` … `user.from_dict(data, new_user=False)` / `db.session.commit()` (no comparison with `token_auth.current_user().id`; `from flask import request, url_for, abort` imports `abort` but nothing uses it) | claude | open |
| F-01-2 | P1 | app/models.py:264 | The API bearer token is `md5(f'{self.id}{now.timestamp():.0f}')`. Its only inputs are the user id and the issue time in whole seconds, so it can be guessed. An attacker who knows a user id and roughly when they logged in can try a few thousand candidates against any `token_auth` endpoint. Combined with finding 1, that gives full account takeover. `secrets` is imported at line 4 but never used, so a CSPRNG token was probably replaced. | `self.token = md5(f'{self.id}{now.timestamp():.0f}'.encode()).hexdigest()` (line 4: `import secrets`, no other use in the file) | claude | open |
